# duckdb-odata Task Checklist — v0.2（认证授权深化、流式与远程执行）

> 依据：docs/design.md §4「v0.2：安全、分页、流式与远程执行」。
> 状态图例：`[x]` 已完成并验证；`[ ]` 未完成/部分完成。
> 已实现的认证基础、列级白名单、分页、资源限制能力随 v0.1 占位发布。

## 1. 认证与授权

- [ ] 认证策略可插拔：API Key / Basic Auth / JWT
- [ ] 授权模型：`odata_grant(user, entity, 'SELECT')`
- [ ] 授权决策链落地：HTTP user → entity → policy → 列/行 → SQL
- [ ] Row-Level Security（tenant 过滤谓词注入）

## 2. 分页

- [ ] `$count` 与数据查询合并执行 + 快照一致性

## 3. 生命周期配置

- [ ] `CALL odata_serve(..., database := 'main')` 指定目标数据库

## 4. 流式输出与资源上限

- [ ] DataChunk → JSON encode → HTTP stream 流式链路（替代整包缓冲）
- [ ] Date/Timestamp ISO8601（`T` 分隔 + 时区）规范化序列化

## 5. QuackExecutor 与远程执行（Milestone 6）

- [ ] `QueryExecutor` 增加 `QuackExecutor` 实现（复用 quack_serve/quack_query，不重实现协议）
- [ ] OData/Gateway 部署形态：编译产物经 Quack 发送到远端 DuckDB
- [ ] 本地/远程执行路径共享 parser/compiler/metadata/serializer（仅换 ExecutionBackend）
- [ ] `CALL odata_proxy('quack://db-server:8815', '/odata')` Gateway 注册（§4.8）
- [ ] transport 层目录拆分落地（src/odata 语义层 vs src/transport/local+quack）

## 6. 其他（§4.10 与 §2 工程约束延续）

- [ ] 阶段二编译：AST → DuckDB Expression / Logical Operator（pushdown 利用）
- [ ] 表达式/字面量进一步参数化（Prepared Statement 形态，防注入纵深）
- [ ] HTTP/1.1 增强：keep-alive、分块响应正确性、超时控制
- [ ] 基准：大结果集（如 100 万行）内存占用与延迟测量
